# VGRAM — полное техническое задание

Этот документ объединяет пожелания владельца проекта. Он описывает целевое приложение, а не автоматически подтверждает готовность каждой функции. Реализация считается готовой только после успешной сборки и проверки на Android-устройстве.

## 1. Основа и совместимость

- Название: **VGRAM**, начальная версия **0.1**.
- Репозиторий разработки: [VGRAM-Main](https://github.com/ramzilzokirov-lgtm/VGRAM-Main).
- Старый репозиторий [VGRAM](https://github.com/ramzilzokirov-lgtm/VGRAM) сохраняется и не должен изменяться в рамках этой работы.
- Основа — исходный код Telegram for Android. Клиент должен подключаться к инфраструктуре Telegram; отдельный сервер сообщений не создаётся.
- Не обходить подтверждение номера, коды входа, облачный пароль и другие механизмы безопасности Telegram.
- Использовать собственные корректно настроенные Telegram API credentials и соблюдать условия распространения исходного кода.
- Сборка и проверка выполняются через GitHub Actions, чтобы владелец мог работать с телефона без ПК.

## 2. Дизайн VGRAM

- Цельный редизайн интерфейса, а не только переименование Telegram.
- Тёмная графитовая основа, приглушённые золотисто-жёлтые акценты, спокойные контрасты и минимализм.
- Визуальный язык Liquid Glass: полупрозрачные панели, тонкие контуры, мягкие градиенты, аккуратные скругления и глубина слоёв. Прозрачность не должна снижать читаемость.
- Material 3-inspired компоненты, единые отступы, типографика, кнопки, карточки, переключатели и состояния загрузки.
- Плавные короткие анимации; отдельный переключатель отключения анимаций для производительности и доступности.
- Экран настроек VGRAM с выбором акцентного цвета, стеклянного оформления, анимаций и сбросом к настройкам по умолчанию. Настройки сохраняются между запусками.
- Переделать экран списка чатов, профиль и страницы настроек постепенно, не ломая стандартные функции Telegram.
- Возможность пользовательского фона профиля с выбором изображения, кадрированием, предпросмотром, удалением и безопасным хранением выбранного файла.
- Проверить статические элементы на OLED-экранах и избегать чрезмерно ярких неподвижных деталей, чтобы уменьшить риск остаточного изображения.
- Иконка приложения в оригинальном стиле, вдохновлённом Узи/Ви из сериала «Дроны-убийцы»; не использовать чужой логотип как будто он официальный. Подготовить адаптивные Android launcher icons разных плотностей.

## 3. Экран разработчиков и информация о приложении

Встроенный экран «Разработчики» должен открываться внутри приложения, а не просто отправлять пользователя в браузер:
- **ramzilzokirov-lgtm** — автор и владелец проекта VGRAM, ссылка на GitHub.
- **ChatGPT** — ИИ-помощник: идеи, проектирование и технические подсказки.
- Отображать версию приложения, ссылку на исходный код, лицензионные сведения и контакты/ссылку проекта, если они настроены.

## 4. Обновления VGRAM (OTA)

- Отдельная встроенная страница «Обновления VGRAM».
- Получать актуальный релиз, версию, описание изменений и ссылку на APK из GitHub Releases.
- Показывать состояние проверки и загрузки, прогресс, ошибки сети, отсутствие новых версий и отмену загрузки.
- Проверять целостность загруженного APK по опубликованному SHA-256; для более строгой защиты — проверять подпись/подписанные метаданные релиза.
- Перед установкой показывать системный диалог Android. Не обходить системное разрешение установки неизвестных приложений.
- Для установки поверх существующего приложения нужна согласованная подпись APK и совместимый package ID/versionCode.
- Документировать разрешения, порядок обновления и восстановление предыдущей версии. Не заявлять о бесшовном автоматическом обновлении: Android требует подтверждения пользователя.
- Публиковать APK, release notes и версию в каждом релизе. Обновление должно работать из страницы приложения, а не только открывать веб-страницу релизов.

## 5. Бейджи VGRAM

- Набор оригинальных небольших бейджей рядом с именем/никнеймом только внутри VGRAM. Вдохновение персонажами «Дронов-убийц»: N, V, J и Узи; прозрачный фон, без лишней плашки и с читаемым силуэтом в маленьком размере.
- Дополнительные категории, которые обсуждались: **TESTER**, **OG/OLD**, **FRIENDS**, **TEAM**. Список и оформление могут настраиваться владельцем.
- Владелец проекта `ramzilzokirov-lgtm` должен иметь интерфейс выдачи и снятия бейджа из профиля пользователя.
- Управление должно быть ограничено реальной проверкой прав на доверенной стороне. Одного скрытого пункта меню или проверки имени на клиенте недостаточно: модифицированный APK можно изменить.
- Если нет доступного доверенного сервиса авторизации/хранения, локальная демонстрационная система должна быть прямо обозначена как незащищённая и не должна выдавать себя за подтверждённый статус.
- Бейдж означает статус внутри VGRAM, а не верификацию со стороны Telegram.

## 6. Система плагинов

Начальная версия должна быть безопасной и расширяемой:
- Версионированный Plugin API с проверкой совместимости.
- Декларативные плагины для цветовых тем, типографики, разрешённых пресетов анимации и простых настроек.
- У каждого плагина: стабильный ID, название, версия, описание, версия API и список разрешённых возможностей.
- Отдельный экран плагинов: просмотр, включение/отключение, удаление, несовместимость и ошибки.
- Явное согласие пользователя перед предоставлением каждой возможности; минимум разрешений по умолчанию.
- Не исполнять произвольные загруженные Java/Kotlin, DEX, JAR, нативные библиотеки или скрипты в первой версии.
- Документация разработчика: формат манифеста, примеры, ограничения API, правила версионирования, установка и удаление.
- Подробности и ограничения: [PLUGIN_API.md](PLUGIN_API.md).

## 7. Вход и надёжность

- Проверить полный сценарий входа: номер телефона, код из SMS или Telegram, повторный запрос кода, таймер ожидания, сетевые ошибки, двухэтапная проверка и выход из аккаунта.
- Не обещать исправление доставки SMS без воспроизведения ошибки: доставка зависит также от Telegram, номера, оператора и ограничений запросов.
- Не выводить коды входа, токены, API secrets или приватные данные в логи.
- Обрабатывать отсутствие сети, отмену действий, ошибки файлов и нехватку места.
- Не ухудшать обычные чаты, звонки, уведомления, медиа, поиск и системную навигацию Telegram.

## 8. Версии, сборка и критерии готовности

- Начальная версия — 0.1; CI может добавлять номер сборки к версии APK.
- GitHub Actions должен собирать APK, сохранять артефакт и публиковать релиз только при успешной сборке.
- Секреты Telegram API и ключи подписи не должны храниться в открытом виде в репозитории.
- Сборка считается успешной только при завершённой компиляции и наличии APK-артефакта. Реальная совместимость установки/обновления и поведения UI подтверждается отдельным тестом на устройстве.
- Каждую функцию отмечать выполненной только после интеграции кода и соответствующей проверки.
- Не заявлять «без ошибок» только по успешному прохождению синтаксических проверок или по наличию файла в репозитории.
