# VGRAM Backend 0.1

Самостоятельный backend для VGRAM. Он не подключается к Telegram и не использует Telegram API. Номер `+888…` — внутренний идентификатор пользователя VGRAM, а не настоящий телефонный номер; принимать SMS на него нельзя.

## Бесплатное тестовое развёртывание

Цель этой конфигурации — не создавать платные ресурсы. В Render используется только план **Free** для веб-сервиса, а база данных размещается отдельно на бесплатном PostgreSQL, например Neon Free. Бесплатные тарифы имеют ограничения и не подходят для гарантированной работы production-мессенджера.

1. Создайте PostgreSQL-проект на [Neon](https://neon.tech/) с тарифом Free и скопируйте connection string. Не отправляйте его в чат и не коммитьте в GitHub.
2. В Render выберите создание Blueprint из репозитория `ramzilzokirov-lgtm/VGRAM-Main`, ветка `backend/bootstrap`, путь `backend/render.yaml`.
3. Убедитесь, что у веб-сервиса выбран тариф **Free**. Blueprint не создаёт платную базу Render: переменная `DATABASE_URL` запрашивается отдельно.
4. Введите connection string Neon в секретное поле `DATABASE_URL` в настройках сервиса. Используйте URL с SSL, который выдаёт Neon.
5. `JWT_SECRET` генерируется Render автоматически. Не публикуйте его.
6. После успешного deploy откройте адрес сервиса с путём `/health`; ответ должен содержать `{"status":"ok","service":"vgram-backend"}`. Путь `/docs` открывает API-документацию.

Ограничения: бесплатный Render Web Service засыпает после простоя и может запускаться примерно минуту. Neon Free при простое переводит вычисления в сон. Перед публичным использованием настройте регулярный экспорт базы и проверку восстановления. Не используйте бесплатный Render Postgres для постоянных данных: он истекает через 30 дней. См. официальные условия [Render Free](https://render.com/docs/free) и [Neon](https://neon.tech/pricing).


## API

- `GET /health` — состояние сервиса.
- `POST /v1/auth/register` — создать аккаунт, получить уникальный `+888…`, 1000 стартовых звёзд и токен.
- `POST /v1/auth/login` — вход по имени и паролю.
- `GET /v1/users/me` — текущий пользователь (Bearer token).
- `GET /v1/users/by-number/{number}` — поиск пользователя по внутреннему номеру (Bearer token).
- `GET /v1/stars/balance` — текущий баланс внутренних звёзд VGRAM.
- `GET /v1/stars/history` — последние начисления/операции звёзд.
- `POST /v1/chats` — создать или открыть личный чат по номеру `+888`.
- `GET /v1/chats` — список личных чатов.
- `GET /v1/chats/{conversation_id}/messages` — история сообщений.
- `POST /v1/chats/{conversation_id}/messages` — отправить текстовое сообщение.

Пример регистрации:

```json
{
  "username": "new_user",
  "password": "use-a-long-unique-password",
  "display_name": "New User"
}
```

Пароль должен содержать не менее 12 символов. Имя пользователя — от 3 до 32 символов, латинские буквы/цифры/подчёркивание, начиная с буквы. Номер выдаётся сервером автоматически. Звёзды пока являются стартовым балансом в базе, а не купленной валютой и не настоящими Telegram Stars.

## Важно

Реализованы базовые HTTP API для личных текстовых чатов, истории сообщений и чтения баланса/истории звёзд. Это всё ещё начальный серверный каркас: группы, доставка сообщений в реальном времени, загрузка медиа, блокировки, модерация, настоящая система покупок/звёзд, бейджи и Android-клиент ещё не подключены. Не считайте продукт готовым мессенджером, пока эти части не реализованы и не проверены. Добавьте лимиты регистрации и мониторинг перед публичным запуском.
